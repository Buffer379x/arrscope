# Validation — 0.7.0

Validation used isolated synthetic libraries on macOS/Apple Silicon. No production Unraid, Radarr, Sonarr or Emby settings were changed.

- All 27 frontend tests, TypeScript, Vite, version consistency, Go race tests and vet passed. The Go vulnerability scanner reported no reachable vulnerabilities (one advisory in an uncalled module). Release CI repeats the dependency audit and scanner.
- New tests cover clock schedules and spring DST, timezone rejection, shared-storage deduplication and mismatched capacities, semantic release comparison, Info count sorting in both services (including all icons hidden and unsafe sort rejection), targeted Radarr/Sonarr reads, authenticated webhook requests, multipart-body rejection, atomic failure retention and retry persistence. Scoped changes preserve unaffected files, manual custom tags and unchanged Emby tracks; per-service webhook credentials remain encrypted and stable across manager restarts. Multiple file events coalesce without duplicate IDs.
- An isolated container end-to-end test queued both service webhooks, restarted during the debounce window, and verified durable jobs/credentials, changed cache revision and exactly five targeted GETs (movie, movie files, series, episode files, episode mapping). There were no full catalog reads, upstream writes or scan calls.
- Browser checks verified INFO headers and ascending/descending controls, CSV query order, removed library subtitles and the Set tag action. Storage showed 16.4 TiB combined rather than summing the shared Downloads filesystem twice; individual scopes showed 10.9 TiB for Movies and 7.3 TiB for TV series. Settings saved a shared group and a 6-hour clock schedule starting at 12:00 in Europe/Berlin; System displayed the next 12:00 slot and a positive version status.
- Desktop and 390-pixel mobile checks inspected storage selection, shared group inputs, colors and System in light/dark modes. The mobile storage grid uses one 358-pixel column with no horizontal body overflow. Desktop storage and language widgets align side by side. Screenshots were inspected inline; file export remains unavailable in the browser runtime.
- The unchanged read-only/non-root 256 MiB/no-swap container fixture passed 100,000 files with two Emby tracks per file and no OOM. Sampled process RSS peak: 220.29 MiB; post-query RSS: 49.58 MiB; HTTP filter p95: 25.158 ms; cached Dashboard p95: 0.905 ms; recognition rewrite sampled RSS peak: 48.54 MiB. Cached Emby metadata survived reprocessing; rule reprocessing made no upstream requests with outbound tags disabled. Measurements are environment-specific; cgroup peaks include filesystem cache.

The first Linux CI run detected an OOM while the application remained running: the former Docker healthcheck started another full application binary, including eager language/recognition initialization. The runtime healthcheck now uses the already-installed BusyBox HTTP probe against the same endpoint, with a three-second timeout and proxy bypass. The 256 MiB/no-swap and OOM gates are unchanged; CI repeats the complete load test before merge.

SQLite remains at schema 11. New settings, background snapshots, encrypted webhook credentials and durable queue records use the existing settings/KV storage. No media mounts or scan commands are added. Webhooks are off and storage paths are unselected by default. Full synchronization is retained for recovery and new Emby audio-track enrichment. CI and release repeat architecture, security and performance gates before stable promotion; no gates are relaxed.
