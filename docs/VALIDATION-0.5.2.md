# Validation — 0.5.2

Local validation used macOS/Apple Silicon with an ARM64 Docker container. External requests used isolated synthetic Arr/Emby fixtures; no production library or credentials were used.

- The final Go race suite and vet passed. Outbound tests cover append/replace decisions, group Keep/Delete retirement, previously kept groups, shared labels, empty-definition cleanup, referenced definitions, restart recovery, custom-assignment ownership, connection changes and required decisions. Fixtures reject unexpected write routes and editor payloads. Usage checks fail closed when media usage is absent or unknown; HTTP 409 preserves definitions that acquire references during cleanup.
- UHDBD recognition and migration tests passed. The editable source override wins over generic BluRay; equivalent customized or disabled rules remain unchanged, and resolution is not inferred by this source rule.
- All 15 frontend tests and the TypeScript/Vite build passed. Translation keys and placeholders match across English, German, Spanish and Italian. Confirmation tests cover deferred action, cancellation and overlapping requests; tag-policy tests cover activation, retirement, mode and address changes.
- Browser checks using a separate synthetic service confirmed explicit choices before settings writes, disabled submission without a choice, Add preserving foreign assignments, Keep causing no cleanup, and Delete removing the affected assignment and its unused definition. The language selector fills its card. The collapsed filter has no separator and retains the same 42-pixel search input height as the expanded filter.
- Deletion confirmations now use application-owned dialogs with Cancel/Escape and a muted-red Delete action. A native confirmation from the earlier test build blocked subsequent browser interactions; cancellation of that obsolete dialog requires manual browser control. The replacement dialog has automated coverage; its final visual browser check is pending.
- The unchanged isolated container check passed with 50,000 movie files, 50,000 episode files and two Emby audio tracks per file, an unprivileged user, read-only filesystem and 256 MiB memory/no swap. Sampled application peak RSS was 209.09 MiB, post-query RSS 39.29 MiB, HTTP filter p95 23.445 ms, cold Dashboard 1348.706 ms, cached Dashboard p95 0.678 ms and recognition reprocessing 17164.819 ms. Cached Emby tracks survived reprocessing, which issued zero upstream requests with outbound synchronization disabled. No OOM occurred. Cgroup peak includes reclaimable filesystem cache; these are fixture measurements rather than host-independent guarantees.

The pull-request and release workflows repeat dependency/security checks, race tests, query benchmarks, container validation and architecture-specific image checks before promoting stable. No timeout or memory gates were relaxed. Production Unraid updates remain user-triggered.
