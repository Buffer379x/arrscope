# Validation — 0.7.1

Validation used isolated synthetic libraries on macOS/Apple Silicon. No production Unraid, Radarr, Sonarr or Emby settings were changed.

- All 27 frontend tests, TypeScript/Vite, version consistency, Go race tests and vet passed. Go vulnerability analysis reported no reachable vulnerabilities (one advisory in a required module, outside called packages). CI repeats dependency and runtime-image audits before merge and release.
- Regression tests compare each Audio bucket with the existing list-filter result, including compound codecs and unknown values, verify per-file deduplication and protect cached statistics from caller mutation.
- Storage tests use the reported Movies/Shows/Documentaries/Downloads capacities: no overlapping areas are summed; both shared paths appear once; the newest complete shared sample supplies total/free together. Scope selection, disabled services, stale values, endpoint changes and mismatched shared capacities are covered. Units are decimal GB/TB; used space remains filesystem usage, including other data.
- Browser review verified Audio drilldowns, top-five expansion and independent card heights. Expanding Language changed its height from 466.5 to 754.5 px while Audio stayed 467.5 px and Storage stayed 556.7 px. The compact Info reset and column resets both measured 34 × 34 px. Service connection tests are beside their headings. The dedicated webhook password toggles between password/text with an accessible pressed state and is hidden again when credentials close; secret values were not recorded in reports.
- Desktop and 390 px mobile checks inspected dark/light layouts, the larger 260 px storage donut, area selection and service headings. Mobile body width and scroll width both measured 390 px. Synthetic Downloads showed 2 TB total / 1 TB free, while Movies showed 10 TB total / 3 TB free, without a combined total. Screenshots were reviewed inline; file export remains unavailable in the browser runtime.
- The unchanged read-only/non-root 256 MiB/no-swap container fixture passed 100,000 files (50,000 per service), two Emby tracks per file, with no OOM. Sampled application RSS peak: 221.35 MiB; post-query RSS: 47.19 MiB; HTTP filter p95: 23.398 ms; cached Dashboard p95: 0.580 ms; cold statistics: 1,253.085 ms. Recognition rewrite preserved Emby tracks and made no upstream requests with outbound tags disabled. These environment-specific measurements shared the host with local race tests; cgroup peaks include filesystem cache and reached the limit.

SQLite remains at schema 11. Existing paths, shared-group settings, colors, schedules, credentials and cache remain compatible. No Unraid integration or new upstream writes were added. CI and release retain all existing architecture, security and performance gates; Unraid updates remain user-triggered.

The first release attempt hit the unchanged 10-second cold-statistics request deadline on a shared Linux runner. Both syncs completed, filters passed, and the container stayed healthy without OOM; stable was not promoted. Audio aggregation now uses one pass over a compact covering expression index, retaining exact partial-unknown semantics without repeated full metadata scans. The deadline and all resource gates remain unchanged. The index is maintained by SQLite on writes and added safely to existing schema-11 caches; no table migration is required.
