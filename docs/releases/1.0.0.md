# Scopearr 1.0.0

The first stable release hardens the existing application and cleans up accumulated code while preserving the interface and feature set.

- Prevent configuration/tag-import lock inversion and protect recognition-rule snapshots during outbound tag reconciliation.
- Keep library and dashboard reads available during database writes with explicit read-only transactions. Make snapshot writes cancellable and keep status queries responsive while retaining atomic, generation-checked commits.
- Report failed session revocation, bound concurrent password checks, and reject corrupted stored settings or recognition rules instead of silently falling back or overwriting them.
- Escape SQLite database paths, enforce private database permissions before opening SQLite, and validate Sonarr episode identities and file/series mappings consistently in full and delta syncs.
- Remove a legacy filter bypass, unused helpers, an unreachable view, obsolete CSS and a duplicate embedded image. Share custom-tag deletion cleanup and split large routing, query, settings and table-rendering files into focused components.
- Cache the read-only tag catalog, separate aggregate cache work, load the authenticated application and less frequently used pages on demand, avoid duplicate requests and stale responses, and tolerate unavailable browser preference storage.
- Refresh the GitHub highlights and screenshot gallery using isolated synthetic data.

## Validation

The release is gated by frontend tests, strict TypeScript checks, a production build, Go race tests and vet, dependency scans, 50,000-file performance tests, both image architectures and the 100,000-file container check under a 256 MiB memory limit without swap. Regression tests cover the corrected failure and concurrency paths.

## Upgrade and rollback

Keep the existing `/data` mount and `secret.key`. This release retains schema 14 and introduces no new data migration or credential format. Existing accounts, encrypted keys, cached libraries, presets, rules and display settings remain supported. An unreadable stored configuration now stops startup with an error; restore a valid backup rather than replacing appdata. Upgrades from older schemas retain their existing backup and migration paths.

For a legacy custom data directory containing `?`, the old unescaped path could have placed the active database outside that directory. If its local key exists but the expected `scopearr.db` is missing, startup now refuses an empty initialization. Restore a consistent backup of the previous database to the intended location and retain its matching key. The normal Docker `/data` path is unaffected.

The release workflow promotes `stable` only after validation succeeds. For rollback, retain appdata and select the previous image version; restore its matching pre-upgrade backup when rolling back across older schema migrations.
